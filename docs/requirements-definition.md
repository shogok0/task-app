# 要件定義書

## 1. 文書概要

### 1.1 目的

学生・個人学習者・学習チームが、課題の登録、共有、進捗把握、締切通知を一元的に行える課題管理アプリの要件を定義する。

### 1.2 想定サービス名

- 仮称: 課題管理アプリ

### 1.3 想定提供形態

- Web アプリ
- PWA 対応
- 将来的にモバイル展開可能な設計

## 2. 背景と課題

現状の課題管理には以下の問題がある。

- 個人ごとにメモやカレンダーへ分散し、一覧性が低い
- チーム / クラス課題の共有が煩雑
- 締切忘れが発生しやすい
- 誰が作成した課題か、共有課題か個人課題かが分かりにくい
- 通知が弱く、提出漏れの予防が難しい

## 3. プロダクトゴール

- 課題の登録から提出管理までを迷わず行えること
- 個人課題と共有課題を同じUXで扱えること
- 締切忘れを減らすこと
- クラス / チーム単位の運用に耐えること
- 組織導入や有料プラン化にも拡張できること

## 4. 対象ユーザー

### 4.1 学生

- 自分の課題を登録したい
- 共有された課題を確認したい
- 締切前に通知を受けたい
- 提出済み / 未提出を管理したい

### 4.2 チーム管理者 / 学習リーダー

- 学習会や塾、サークル単位で課題を共有したい
- メンバーの混乱を減らしたい
- 共有課題の修正・削除を行いたい

## 5. スコープ

### 5.1 MVP スコープ

- アカウント登録 / ログイン
- 個人課題の作成 / 編集 / 削除
- 締切付き課題の一覧表示
- 提出済み / 未提出の切替
- クラス / チーム作成
- クラス / チーム参加
- 共有課題の作成 / 閲覧
- 通知設定
- 締切通知メール
- PWA 基本対応

### 5.2 将来スコープ

- 添付ファイル
- コメント
- 課題テンプレート
- 組織管理ダッシュボード
- 分析レポート
- LMS / 外部カレンダー連携
- 課金機能

## 6. 非機能要件

### 6.1 可用性

- 一般利用に耐える安定稼働
- 通知ジョブ失敗時に再試行可能

### 6.2 性能

- 主要画面の初回表示は快適であること
- 一覧画面は実用的な応答速度を保つこと
- 通知処理は同期応答をブロックしないこと

### 6.3 セキュリティ

- 認証されたユーザーのみ個人データへアクセス可能
- クラス / チームの所属に応じて共有データを制御
- 権限外の課題編集・削除を防止
- 招待や参加コードは推測されにくいこと

### 6.4 拡張性

- 将来的な組織課金、組織導入、分析機能追加に対応可能
- Web 以外のクライアントを将来追加できる

### 6.5 運用性

- エラー監視が可能
- 通知配信履歴を確認できる
- 管理者が問題調査しやすいログ構造を持つ

## 7. 業務ルール

- 個人課題は作成者本人が管理できる
- 共有課題は、当該クラス / チームの適切な権限保持者が作成・編集・削除できる
- 提出済み切替は、少なくとも本人ができる
- 通知はユーザーごとの設定に従う
- 通知の重複送信は避ける

## 8. 成功指標

- 継続利用率
- 課題登録数
- 締切前通知の開封 / 到達率
- 提出漏れの減少
- クラス / チーム継続率

## 9. 前提・制約

- 初期リリースは日本語UIを前提とする
- Web ファーストで提供する
- 組織ごとの厳格な承認ワークフローは MVP 対象外
- 成績評価や採点機能は MVP 対象外
