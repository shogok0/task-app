# 機能設計書

## 1. 文書の目的

要件定義に基づき、ユーザーが利用する主要機能の振る舞い、画面責務、権限、入出力を整理する。

### 2.4 通知設定系

- 締切通知バッチ

## 3. 主要ユースケース

### 3.1 個人課題を登録する

#### 目的

ユーザーが自分専用の課題を管理できるようにする。

#### 入力

- 科目名
- 課題名 / 内容
- 締切日
- 所属先未選択

#### 処理

- 入力値を検証する
- 課題を個人課題として保存する
- 一覧に反映する

#### 出力

- 作成済み課題

### 3.2 共有課題を登録する

#### 目的

管理権限のあるメンバーがクラス / チーム向け課題を登録する。

#### 入力

- 科目名
- 課題名 / 内容
- 締切日
- 対象クラス / チーム

#### 処理

- 作成者の権限を確認する
- 共有課題として保存する
- 対象メンバーに表示できる状態にする

#### 出力

- 共有課題

### 3.3 課題を提出済みにする

#### 目的

未提出課題を完了状態に切り替える。

#### 入力

- 対象課題ID

#### 処理

- 課題閲覧権限を確認する
- 提出状態を更新する

#### 出力

- 更新後の課題状態

### 3.4 通知設定を変更する

#### 目的

ユーザーが締切通知の受信方法を設定する。

#### 入力

- メールアドレス
- 通知有効 / 無効
- 何日前に通知するか

#### 処理

- 入力値を検証する
- ユーザー通知設定を更新する

#### 出力

- 更新済み通知設定

## 4. 画面責務

### 4.1 ダッシュボード画面

- 直近の未提出課題を表示
- 緊急度を表示
- 個人課題 / 共有課題を混在表示
- クラス / チーム切替導線を表示

### 4.2 カレンダー画面

- 締切日を日付ベースで表示
- 課題クリックで詳細 / 編集導線へ遷移

### 4.3 通知設定画面

- 通知先と通知条件を編集可能
- 現在の状態を分かりやすく表示

## 5. 権限設計

### 5.1 ロール

- `member`
- `admin`

### 5.2 権限方針

- `member`
  - 自分の個人課題を管理できる
  - 所属クラス / チームの共有課題を閲覧できる
  - 自分が扱える課題の提出状態を更新できる
- `admin`
  - クラス / チーム管理、メンバー管理、共有課題管理ができる

## 6. バリデーション方針

### 6.1 課題作成

- 科目名: 必須、最大長制限あり
- 課題名 / 内容: 必須、最大長制限あり
- 締切日: 必須
- クラス / チーム指定時: 所属確認必須

### 6.2 クラス / チーム参加

- 参加コード: 必須
- 有効なコードのみ参加可能

### 6.3 通知設定

- メールアドレス: 形式チェック
- 通知日前数: 範囲制限

## 7. 非同期機能設計

### 7.1 締切通知ジョブ

#### 起動契機

- スケジュール実行

#### 処理内容

- 通知対象日を算出
- 通知有効ユーザーを抽出
- 未提出課題を収集
- 配信履歴を照合し、重複送信を防ぐ
- メール送信
- 配信結果を記録

### 7.2 将来の Push 通知

- 通知許可済みユーザーのみ対象
- モバイル PWA を優先サポート
- メールと Push は別チャネルとして履歴管理

## 8. エラー時の扱い

- 権限不足: 操作不可として扱う
- 入力不備: フォームエラー表示
- 通知送信失敗: ジョブ側で記録し再試行対象にする
- 参加コード不正: 参加失敗として案内する
